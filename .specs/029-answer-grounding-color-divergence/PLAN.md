# Plan: Answer grounding as color-distribution divergence — a cheap RAG faithfulness signal

## Implementation Strategy

Measure how far a generated answer drifts from its retrieved context by **composing
existing ports**, adding only a thin domain value object, one application use case, one
CLI, and one committed report. Nothing in the ML or distance stack is reimplemented:
embedding comes from `SentenceEmbeddingAdapter`, quantisation from `ColorCodebook`, the
histogram from the `EncodeDocumentUseCase` path, and the divergence from the
`DistanceCalculator` port (features 001 / 019). This is feature 023's *coherence* reading
(beat vs whole-book palette) pointed at retrieval: **answer histogram vs the mixture of
retrieved-passage histograms**.

Three decisions keep it honest:

1. **Reuse ports, add no ML and no new distance.** The use case depends only on the
   `DistanceCalculator` abstraction; the metric (`sliced` / `jensen_shannon` / `exact`) is
   a constructor choice at the CLI boundary.
2. **Distribution, not average.** The context palette is the uniform **mixture** of
   passage histograms, and each passage is a histogram built from its sentences — never a
   mean of Lab colours, which would cancel chroma (the documented aggregation trap). This
   is enforced by construction and pinned by a falsifiable test.
3. **Honest signal.** The report and README state plainly that this detects
   *distributional off-context drift*, not factual error; a small divergence does not
   certify correctness. No overclaiming — consistent with the roadmap's ethos.

MVP-first ordering: the `GroundingReport` value object and `EvaluateGroundingUseCase`
with their tests (tasks 1–2) are the independently-committable core; the CLI, config
block, and committed `reports/grounding_audit.md` (tasks 3–6) complete the feature to the
repo's "committed artifact + generator" convention and can be deferred if a smaller first
landing is preferred.

Canonical output: a committed `reports/grounding_audit.md` regenerated by
`tox -e grounding` over a small checked-in RAG sample (question + retrieved passages + one
grounded and one off-context candidate answer), with the grounded answer below and the
off-context answer above threshold. Unit tests are hermetic (fake distance, synthetic
histograms, no network); only the generator loads the real embedder.

## Layer Changes

### Domain Layer (`src/colors_of_meaning/domain/`)

- `domain/model/grounding_report.py`: frozen `GroundingReport(divergence: float,
  threshold: float)` with an `is_grounded` property (`divergence <= threshold`) and
  non-negativity validation in `__post_init__`. Pure; no framework, no I/O, no distance
  maths inside the model.

### Application Layer (`src/colors_of_meaning/application/`)

- `application/use_case/evaluate_grounding_use_case.py`:
  `EvaluateGroundingUseCase(distance_calculator)` with
  `execute(answer, context, threshold) -> GroundingReport` and
  `execute_against_contexts(answer, contexts, threshold)`. The multi-context variant mixes
  the passage histograms into a uniform-mixture palette (mirroring
  `AnalyzeNarrativeArcUseCase._mix_palette`) and delegates to `execute`. Divergence comes
  only from the injected port; `correlation-id` logging of the verdict record. Raises on
  empty contexts. Depends only on abstractions.

### Infrastructure Layer (`src/colors_of_meaning/infrastructure/`)

- No new adapter. The audit reuses `WassersteinDistanceCalculator` (feature 001),
  `SlicedWassersteinDistanceCalculator` / `JensenShannonDistanceCalculator` (feature 019)
  behind the `DistanceCalculator` port.

### Interface Layer (`src/colors_of_meaning/interface/`)

- `interface/cli/grounding.py`: tyro `@dataclass` args; `_build_pipeline` constructs the
  embedder, mapper + codebook (from artifacts), and distance calculator; `main` encodes the
  answers and passages to histograms via the `EncodeDocumentUseCase` path, runs the use
  case per candidate answer, prints the divergence/verdict table, and writes the report.
- `tox.ini`: new `[testenv:grounding]`.
- `README.MD`: "Grounding audit" section with the `tox -e grounding` example and the
  committed result.
- Architecture test: the CLI's imports stay within interface rules; the use case never
  imports infrastructure.

### Shared Layer (`src/colors_of_meaning/shared/`)

- `shared/synesthetic_config.py`: add an optional `grounding` config section (threshold,
  metric, sample path, report path). No new shared parser — the CLI reads the small
  structured sample file directly.

## Dependency Injection

The CLI builds every collaborator and injects the `DistanceCalculator` into
`EvaluateGroundingUseCase` as an abstraction, exactly where `encode` / `visualize` /
`compass` build their pipelines today. The distance metric
(`sliced` / `jensen_shannon` / `exact`) is selected by CLI arg and resolved to the
concrete adapter at construction. No Lagom container or API wiring changes.

## Testing Strategy

House rules: one logical assertion per test, `test_should_..._when_...` names,
`assert_that` for the `GroundingReport` value object, plain `assert` / `pytest.raises` for
the use-case and ML paths, no network (fake distance + synthetic histograms), hermetic
`tmp_path` for any file output. Key tests:

- **Grounding report (value object):** frozen; `is_grounded` true at and below threshold,
  false above; rejects negative divergence and negative threshold.
- **Use case (fake `DistanceCalculator`):** divergence equals the port's distance;
  `is_grounded` follows the threshold; `execute_against_contexts` hands the port the
  **uniform mixture** of passage histograms (captured and asserted — the anti-aggregation
  guard); a different-topic answer scores strictly higher than a same-topic answer (the
  falsifiable directional claim); empty contexts raise.
- **Config:** the `grounding` block parses with defaults and overrides.
- **CLI:** builds the pipeline from args and writes the report (mock use case); the metric
  flag selects the right adapter.
- **Architecture:** the value object and use case respect layer boundaries (pytest-archon).
- **Determinism / committed artifact:** two runs over the sample produce identical numbers;
  the committed report is regenerated, not asserted byte-for-byte against a golden.

## Observability Plan

`correlation-id` logging in the use case per audited answer:
`{answer_id, context_id, metric, divergence, threshold, is_grounded}`, so a flagged answer
is traceable. No new metrics or tracing.

## Risks and Mitigations

- **Overclaiming factuality.** A grounding *distribution* signal is not a truth checker.
  Mitigation: SPEC, README, and the generated report state explicitly that this detects
  distributional off-context drift, not factual error; small divergence does not certify
  correctness.
- **Chroma cancellation via averaging** (the aggregation trap). Mitigation: the context
  palette is a **histogram mixture**, never a Lab-colour mean; a capture test pins it.
- **Threshold is corpus/metric-dependent** (as feature 023's drift threshold was).
  Mitigation: `--threshold` CLI arg; the committed demo pins a value and documents it as
  calibration, not a universal constant.
- **Distance cost** (exact EMD ~92 ms/call, feature 006 note). Mitigation: default to
  sliced-Wasserstein; exact is opt-in and bounded to the small sample; palette mixing is
  O(passages).
- **Generator loads the embedder** (one-time HuggingFace model download). Mitigation:
  unit tests mock the embedder and use synthetic histograms; only `tox -e grounding` touches
  the model, matching how `compass` / `authorship` generate their artifacts.
- **`.gitignore reports/*` swallowing the committed report** (feature 028 gotcha).
  Mitigation: add `!reports/grounding_audit.md` and assert the file is tracked.
- **Cross-machine non-determinism.** Mitigation: `seed_everything`; a repeated-run test
  asserts identical output over the sample.
- **Scope creep into an API or an LLM.** Mitigation: CLI-only, answers and passages
  provided as a checked-in file; the guardrail endpoint and any live generation are
  explicitly out of scope (the endpoint is an Open Question).
