# Plan: Narrative color compass — a story arc as a measurable color trajectory

## Implementation Strategy

Turn an ordered story outline into a measured colour trajectory by **composing
existing ports**, adding only a thin domain arc model, one application use case, one
renderer method, one pure parser, and one CLI. Nothing in the ML or distance stack is
reimplemented: embedding comes from `SentenceEmbeddingAdapter`, the interpretable
colour from the structured mapper (feature 008), quantisation from `ColorCodebook`,
the drift metric from the `DistanceCalculator` port (features 001 / 019), and the
figure from `MatplotlibFigureRenderer` behind the `FigureRenderer` port.

Two readings per beat, kept deliberately distinct:

1. **Interpretable axes** — embed the beat's *whole text* once and read
   lightness/chroma/hue through the structured mapper. This is a document-level read,
   never a mean of sentence colours, because averaging Lab cancels chroma and would
   silently destroy the concreteness axis.
2. **Drift / coherence** — render the beat's sentences into a `ColoredDocument`
   histogram and measure `DistanceCalculator` distance beat-to-beat and beat-to-palette.
   A histogram is a distribution, so this reading is safe from the aggregation trap and
   reuses the project's real Earth-Mover machinery.

Three decisions keep it honest:

1. **Reuse ports, add no ML.** The use case depends only on `ColorMapper`,
   `ColorCodebook`, `DistanceCalculator`, and `FigureRenderer` abstractions; swapping
   the distance metric or the mapper is a constructor choice.
2. **Beats are provided, not generated.** The compass never calls an LLM. The outline
   is an input file, which keeps this feature fully CI-reproducible and forms the clean
   seam feature 024 plugs into.
3. **Document-embedding colour, histogram drift.** The single anti-aggregation rule is
   enforced by construction and pinned by a falsifiable test.

Canonical outputs: a committed `reports/story_compass.md` and
`reports/figures/story_compass.png` regenerated by `tox -e compass` over a small
checked-in sample outline (no external dependency, reproducible in CI).

## Layer Changes

### Domain Layer (`src/colors_of_meaning/domain/`)

- `domain/model/narrative_arc.py`: frozen `NarrativeBeat(index, title, text)`,
  `ArcPoint(beat, colour, histogram)`, and `NarrativeArc(points, drift_series,
  coherence_series)` with a `flagged_beats(threshold)` view. Pure; reuses `LabColor`
  and `ColoredDocument`; no framework, no I/O, no distance maths inside the model.

### Application Layer (`src/colors_of_meaning/application/`)

- `application/use_case/analyze_narrative_arc_use_case.py`:
  `AnalyzeNarrativeArcUseCase(embedding, structured_mapper, codebook,
  distance_calculator).execute(beats) -> NarrativeArc`. Per beat: embed whole-beat
  text → structured colour; encode sentences → `ColoredDocument`; then build the
  drift series (consecutive beats) and coherence series (beat vs mixed palette) via the
  port. `correlation-id` logging at start/summary.

### Infrastructure Layer (`src/colors_of_meaning/infrastructure/`)

- `infrastructure/visualization/matplotlib_figure_renderer.py`: add
  `render_narrative_arc(arc, output_path)` — fixed-axis panels for lightness, chroma,
  hue, and the drift series, plus a beat-colour swatch strip (Lab→RGB via
  `shared/lab_utils.py`). Declared on the `FigureRenderer` port so the domain boundary
  holds.

### Interface Layer (`src/colors_of_meaning/interface/`)

- `interface/cli/compass.py`: tyro `@dataclass` args; `_build_pipeline` constructs the
  embedder, structured mapper + codebook (from artifacts), distance calculator, and
  renderer; `main` runs the use case, prints the drift/coherence table, writes the
  report, and renders the figure.
- `tox.ini`: new `[testenv:compass]`.
- `README.MD`: "Narrative compass" section with the `tox -e compass` example and the
  committed sample figure.
- Architecture test: the CLI's imports stay within interface rules; the use case never
  imports infrastructure.

### Shared Layer (`src/colors_of_meaning/shared/`)

- `shared/outline_parser.py` (pure, no I/O): `parse_outline(text, min_chars) ->
  List[NarrativeBeat]` (heading/blank-line delimited, too-short blocks dropped).
- `shared/synesthetic_config.py`: add a `compass` config section (drift threshold,
  minimum beat length, mapper choice, metric, report/figure paths).

## Dependency Injection

The CLI builds every collaborator and injects it into `AnalyzeNarrativeArcUseCase` as
an abstraction, exactly where `encode`/`visualize` build their pipelines today. The
mapper (`structured` vs `plain`) and the distance metric (`sliced`/`jensen_shannon`/
`exact`) are selected by CLI arg and resolved to the concrete adapter at construction.
No Lagom container or API wiring changes.

## Testing Strategy

House rules: one logical assertion per test, `test_should_..._when_...` names,
`assert_that` for the arc value object, plain `assert`/`pytest.raises` for the ML/
distance paths, no network, hermetic `tmp_path` for any file output. Key tests:

- **Outline parser:** headings/blank lines split into ordered beats; too-short and
  whitespace-only blocks dropped; indices are contiguous.
- **Arc model:** frozen; `flagged_beats` returns exactly the beats above threshold;
  point order matches input order.
- **Use case (mocked collaborators):** N beats → N points in order; drift series length
  is N−1 and each value comes from the fake distance; coherence measured against the
  mixed palette; **anti-aggregation** — a beat with opposing-hue sentences keeps chroma
  because the colour is read from the document embedding.
- **Renderer:** one real render to `tmp_path` asserts the PNG is produced at the
  configured size with non-cropped axes (guards against a real matplotlib crash a
  mock would hide).
- **CLI:** builds the pipeline from args and writes report + figure (mock use case +
  renderer); metric/mapper flags select the right adapter.
- **Determinism / committed artifact:** two runs over the sample outline produce
  identical numbers; the committed report is regenerated, not asserted byte-for-byte
  against a golden.

## Observability Plan

`correlation-id` logging at analysis: `{beats, per_beat_lchue, drift_summary,
coherence_summary, flagged_count, palette_entropy}`. No new metrics or tracing.

## Risks and Mitigations

- **Chroma cancellation via averaging** (the aggregation trap). Mitigation: read the
  beat colour from the document embedding, never the sentence-colour mean; a
  falsifiable test with opposing-hue sentences pins it.
- **Mocked-renderer blind spot** (a mock hides a real matplotlib crash, as happened in
  the corpus-visualisation work). Mitigation: one real render to `tmp_path` in CI.
- **Distance cost** (exact EMD ~92 ms/call). Mitigation: default to sliced-Wasserstein;
  exact is opt-in and bounded to short outlines; palette mixing is O(beats).
- **Missing structured artifact.** Mitigation: `--mapper plain` fallback yields a valid
  colour without axis semantics; the report notes when axes are unavailable.
- **Cross-machine non-determinism.** Mitigation: `seed_everything`; deterministic beat
  ordering from the parser; a repeated-run test asserts identical output.
- **Scope creep into an API or an LLM.** Mitigation: CLI-only, beats provided as a
  file; the arc-analysis endpoint and the generator that produces beats are explicitly
  out of scope (the endpoint is an Open Question; generation is feature 024).
